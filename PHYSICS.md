# Базовая физика PhysX

Подключён NVIDIA PhysX 5.5.0 через vcpkg, baseline закреплён в `vcpkg.json`.
Используются CPU-симуляция и статические SDK-библиотеки с динамическим CRT
(`x64-windows-static-md`). GPU physics, cooking, персонажи и суставы не добавлялись.

## Сборка и запуск

Из корня проекта в PowerShell:

```powershell
./scripts/build-physics.ps1
./scripts/test-physics.ps1
& ./out/build/x64-physx-debug/Editor/Editor.exe --physics-test
```

Новая сцена находится в `Editor/PhysicsTestScene.h` и `.cpp`.
Без `--physics-test` редактор создаёт прежнюю сцену: её исходный блок сохранён без изменений.
`Game.exe` по-прежнему имеет исходную пустую точку входа; демонстрация запускается через Editor.

Нужны Visual Studio с C++ tools, Windows SDK, CMake/Ninja и vcpkg. Скрипт находит
Visual Studio через vswhere; можно задать `VCPKG_ROOT` для другой установки vcpkg.
Машинные абсолютные пути в конфигурации проекта не записываются. При первом запуске
нужна сеть. Порт vcpkg также загружает дополнительные бинарные части SDK; симуляция
не использует GPU. Порт поддерживается vcpkg, а не NVIDIA.

Скрипт сборки передаёт пустой `CMAKE_PROJECT_TOP_LEVEL_INCLUDES`, поскольку существующий
пресет ссылается на отсутствующий в установленной VS `SegmentHeap.cmake`.
Сам пресет не изменён. Тестовый скрипт компилирует отдельный консольный набор проверок;
он не правит сгенерированные файлы проекта и не добавляет тестовый код в Editor.

Редактор остаётся консольным приложением согласно исходной конфигурации CMake.
Обычный запуск может показывать дополнительную консоль. Её закрытие завершает приложение.
Для проверки без консоли можно запустить бинарник через ProcessStartInfo с
`UseShellExecute = false`, `CreateNoWindow = true`; это не меняет графическое окно сцены.

## Что показывает сцена

PhysicsTestScene заменена на 3D-демонстрацию с перспективой, камерой под углом,
цветными гранями и проверкой глубины:

- Пол: центр `(0, -0.2, 0)`, размеры `(8, 0.4, 8)`, статическое тело. Верх пола находится на Y=0.
- Оранжевый куб: центр `(-1, 5, 0)`, размеры `(1, 1, 1)`, поворот по Y на 0.45 рад,
  динамическое тело массой 2. После падения ожидается высота центра Y=0.5.
- Бирюзовый объект без физики: центр `(2, 1, -1)`, размеры `(0.7, 0.7, 0.7)`.
- Гравитация стандартная: `(0, -9.81, 0)`.

Камера расположена в `(8, 7, -10)`, смотрит на `(0, 1.8, 0)`; вертикальный угол обзора
45 градусов, near/far 0.1/100, соотношение сторон берётся из размеров окна.

RenderServer, шейдеры и форматы GPU-буферов не изменены. Поскольку существующий рендер
принудительно использует единичные view/projection, локальный компонент PhysicsTestBoxComponent
в `Editor/PhysicsTestView.h` передаёт готовую матрицу `world * view * projection` через поле
RenderItem::world. Матрица физического TransformNode при этом остаётся в мировых координатах.
Перспективное деление выполняется обычным графическим конвейером по координате W.
Обычный MeshComponent по-прежнему передаёт только worldMatrix.

Компонент использует существующие CreateRectangle, CreateSimple и CreateOpaque. Цвета граней
задаются в CPU-геометрии, порядок треугольников согласован с отсечением граней CreateOpaque.
Цвета создают фиксированные оттенки граней; динамическое освещение не добавлялось.
Камера фиксирована. Новых файлов сборки и правок CMake для 3D-демонстрации нет.
## Как добавить физику объекту

```cpp
#include "core.h"
#include "Physics/PhysicsComponents.h"

Game game(L"Example");
GameObject object;
MeshComponent mesh;
BoxColliderComponent box({1.0f, 1.0f, 1.0f}, {0.6f, 0.5f, 0.0f});
DynamicRigidBodyComponent body(box, 2.0f);
Level level;

object.fetTransform().set_position({0, 0.5f, 0.5f});
object.fetTransform().set_scale({0.2f, 0.2f, 0.2f});
mesh.bind_to_node(&object.fetTransform());
body.bind_to_node(&object.fetTransform());
object.addComponent(mesh);
object.addComponent(box);
object.addComponent(body);
level.addObject(&object);
game.setStartLevel(&level);
game.Init();
return game.Run();
```

Для неподвижного объекта используется `StaticRigidBodyComponent body(box)`.
Параметры материала по порядку: статическое трение, динамическое трение, упругость.
Размеры box — полные локальные размеры по X/Y/Z, не полуразмеры. Масса задаётся явно;
PhysX вычисляет инерцию по фактическим размерам формы через setMassAndUpdateInertia.

Настройки коллайдера копируются в тело при его конструировании. Их последующее изменение
не меняет уже созданное тело. Коллайдер без тела ничего не регистрирует в физической сцене.
Меши без тела/коллайдера сохраняют обычное поведение.

## Синхронизация и ограничения

Game использует существующее число fixed-step и интервал TimeManager, без второго
аккумулятора. В каждом шаге выполняются simulate и блокирующий fetchResults; только затем
позиция и quaternion динамических тел записываются в TransformNode. Масштаб сохраняется.
Перед DrawAll вызывается виртуальный SyncTransform зарегистрированных RenderComponent. Базовый компонент копирует worldMatrix; компонент тестовой 3D-сцены дополнительно применяет вид и перспективу.

Первая версия поддерживает только корневые физические TransformNode. Родитель отклоняется
даже при выключенных флагах наследования. Размеры и масштаб должны быть конечными и
положительными, quaternion — единичным, масса — положительной, трение — неотрицательным,
упругость — в диапазоне `[0, 1]`.

Изменение масштаба либо родителя после создания тела диагностируется при следующем шаге
и останавливает Run с ненулевым кодом. То же относится к изменению позы статического тела.
Для изменения этих параметров сначала вызвать `body.Detach()`, изменить TransformNode,
затем `body.Attach(game.getPhysicsWorld())`. Ручное изменение позы динамического TransformNode
не является телепортацией: очередной шаг вернёт актуальную позу PhysX. Для телепортации
в этой версии также требуется Detach/Attach. Физика выполняется на основном потоке;
одновременное изменение компонентов из других потоков не поддерживается.

## Владение и уничтожение

- PhysicsWorld владеет foundation, physics, CPU dispatcher, scene и зарегистрированными
  actors. Actor удерживает exclusive shape, shape удерживает material. Временные ссылки
  shape/material освобождаются сразу после передачи владения. Мировые объекты уничтожаются
  после освобождения actors: scene, dispatcher, physics, foundation.
- RigidBodyComponent содержит невладеющую регистрацию. Его деструктор удаляет actor.
  Shutdown мира обнуляет регистрации переживших его компонентов. Инициализация SDK и тел
  проверяет возвращаемые указатели и очищает частично созданные ресурсы, без новых исключений.
- TransformBinding — невладеющая связь компонента с TransformNode. Уничтожение узла
  отсоединяет связанные физические тела до освобождения трансформации; уничтожение компонента
  удаляет его связь из узла. Эти связи нельзя копировать.
- Game содержит невладеющий список RenderComponent для синхронизации. Деструктор компонента
  удаляет регистрацию; деструктор Game отсоединяет пережившие его компоненты до удаления рендера.
- RenderComponent владеет RenderItem и эксклюзивными mesh/material/shader/state, возвращёнными
  существующим CreateSimple. Производный компонент обязан соблюдать тот же контракт;
  общий пул или совместное владение ресурсами здесь не вводились.
- GameObject/Level по-прежнему невладеющие. Компоненты и объекты должны жить во время Init/Run.
  Их деструкторы не обходят сохранённые указатели. В PhysicsTestScene компоненты объявлены
  после объектов, Game — до них, поэтому порядок разрушения безопасен.

## Фактическая проверка

3D-версия собрана в x64 Debug. Автоматические проверки из scripts/test-physics.ps1
выполнены успешно, RESULT failures=0:

- Падение с Y=5 и контакт на Y≈0.5, сон и ещё пять секунд устойчивого покоя.
- Неподвижность статического пола и объекта без физики, сохранение масштаба.
- Масса 2 и инерция куба `(1/3, 1/3, 1/3)`.
- Одинаковый результат для группировки fixed-step по render-кадрам 30/144 Гц.
- Начальная позиция куба внутри перспективной камеры; при удвоении расстояния
  экранная ширина объекта уменьшается вдвое.
- Виртуальный вызов SyncTransform через RenderComponent применяет перспективу,
  падение меняет экранное положение, физические координаты и масштаб не проецируются.
- Расчёт инерции при неравномерном масштабе, quaternion, неверные параметры,
  изменение масштаба через Detach/Attach, разные порядки уничтожения компонентов,
  узла и мира, частичная ошибка инициализации и восстановление.
- CRT-проверка не обнаружила оставшихся выделений памяти после сценариев физики.

Графическое окно фактически показало платформу и объёмные цветные кубы в перспективе.
После этого исправлен порядок треугольников для корректной видимости внешних граней;
повторная сборка и автоматические тесты прошли. Повторный визуальный просмотр финальной
правки не выполнялся: пользователь остановил Computer Use клавишей Esc. Тестовый запуск
завершился с кодом 0. Визуально весь цикл падения финальной 3D-версии отдельно не подтверждён.

Проверено побайтное совпадение RenderServer.h/.cpp, шейдера, CMake-файлов, компонентов
физического модуля и Editor/main.cpp с копиями до замены сцены. Ранее проверенная исходная
сцена при обычном запуске остаётся без изменений. Единственное изменение существующего
компонентного интерфейса для 3D — виртуальный SyncTransform; реализация базового метода
и обычный MeshComponent не менялись.
