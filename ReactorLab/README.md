# Reactor Lab — Аварийный реактор

Отдельный проект GGEngine. Вся игровая логика написана на Lua; CMake и исходники движка не изменялись.

**Статус: проект подготовлен, но полное прохождение на приложенной сборке заблокировано авариями в Lua API движка.** Подробности и воспроизведение — в `TEST_REPORT.md`. Не считать этот архив подтверждённо работоспособным релизом игры.

## Игра

За 90 секунд соберите три золотых энергоблока и доберитесь до EXIT в правом нижнем углу. Голубой квадрат — игрок, красный — дрон. Центральная красная полоса включается и выключается каждые две секунды. У игрока три единицы здоровья и 1,5 секунды неуязвимости после попадания.

- WASD — движение в плоскости XY.
- R — перезапуск раунда без перезагрузки сцены.
- Верхние полосы показывают время, здоровье и долю собранных блоков.
- Нижние надписи показывают выбранное действие дрона: Patrol, Chase или Recharge.

Дрон патрулирует, преследует близкого игрока и возвращается на зарядку при низкой энергии. Решение принимает настоящий UtilityAIComponent по таблице и кривым. Скорость и движение задаются Lua-действиями.

## Открытие

Распакуйте весь архив. Откройте `ReactorLab/ReactorLab.ggproject` через Open Project в редакторе. Стартовая сцена — `res://Scenes/Main.level.json`.

Рядом с проектом находится `Runtime`: копия уже собранного Game.exe и стандартных ресурсов. Она не пересобиралась. Для прямого запуска предназначен `ReactorLab/Launch.cmd`. До исправления указанных в отчёте ошибок сборки этот запуск может аварийно завершиться.

Можно передать другую сборку явно:

```cmd
Launch.cmd "C:\path\to\Game.exe"
```

## Структура проекта

| Путь | Назначение |
|---|---|
| `ReactorLab.ggproject` | Манифест версии 1, корень ресурсов и стартовая сцена |
| `res/Scenes/Main.level.json` | Игровая сцена |
| `res/Scenes/Autoplay.level.json` | Та же игра с автоматическим маршрутом игрока |
| `res/Scenes/Tests.level.json` | Общий регрессионный сценарий четырёх систем |
| `res/Scenes/Check*.level.json` | Независимые проверки, которые прошли на готовом Game.exe |
| `res/Scenes/Repro*.level.json` | Минимальные воспроизведения аварий |
| `res/Scripts` | Логика игры, регистрация экземпляров, индикаторы, тесты |
| `res/AI` | Таблицы UtilityAI, кривые и Lua-действия |
| `res/Materials`, `res/Textures` | Материалы и текстуры; надписи запечены в PNG |
| `verification` | Фактические результаты запусков и исходные логи |

Каждый объект и компонент сериализован штатным форматом движка. Timer и UtilityAI находятся в обычных компонентах объекта; визуальные, физические и Lua-компоненты — в TransformTree. Размер визуального элемента задан дочерней веткой, чтобы не менять размер физического тела. Ссылки на ресурсы используют `res://`, согласно текущей реализации и LUA_API.md.

`World.lua` — небольшой реестр живых Lua-экземпляров сцены, поскольку публичного поиска объектов по именам нет. Он не владеет C++-объектами. Игровое состояние хранится в экземплярах компонентов. Проект не добавляет систем в движок.

## Проверки

Из PowerShell в папке ReactorLab:

```powershell
.\Test.ps1 -Scene CheckTimer
.\Test.ps1 -Scene CheckDelegates
.\Test.ps1 -Scene CheckTrigger
.\Test.ps1 -Scene CheckAI
```

Скрипт запускает отдельный процесс и сохраняет его stdout/stderr в `logs`. Успех требует строки COMPLETE без неудачных проверок; сам факт запуска окна успехом не считается. После результата закрывается только созданный процесс.

После устранения ошибок движка:

```powershell
.\Test.ps1                 # общий сценарий, включая физические входы/выходы
.\Test.ps1 -Autoplay       # автоматический сбор трёх блоков и выход
```

Для новой сборки добавьте `-GameExe "C:\path\to\Game.exe"`. Режимы `-Scene ReproTimerEvent`, `ReproTriggerEvent`, `ReproInstance` на текущей сборке воспроизводят аварии и завершают проверку с ошибкой. После исправления их также можно открывать непосредственно в редакторе: ожидается строка AFTER после строки BEFORE.

Персонажи кинематические; границы площадки ограничены в Lua. Навмеш, полноценные стены, звук и текстовый UI не используются. Размеры и расположение интерфейса требуют визуальной проверки после устранения блокирующих ошибок.
