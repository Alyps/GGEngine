# Reactor Lab — Аварийный реактор

Игровой проект для ветки `QA` GGEngine. Для запуска нужна сборка этой ветки. Автоматическое прохождение и результаты проверок описаны в [TEST_REPORT.md](TEST_REPORT.md).

## Игра

За 90 секунд соберите три золотых энергоблока и доберитесь до EXIT в правом нижнем углу. Голубой квадрат — игрок, красный — дрон. Центральная красная полоса включается и выключается каждые две секунды. У игрока три единицы здоровья и 1,5 секунды неуязвимости после попадания.

- WASD — движение в плоскости XY.
- R — перезапуск раунда без перезагрузки сцены.
- Верхние полосы показывают время, здоровье и долю собранных блоков.
- Нижние надписи показывают выбранное действие дрона: Patrol, Chase или Recharge.

Дрон патрулирует, преследует близкого игрока и при энергии 30 или ниже возвращается на док. Зарядка продолжается до 100. Действие выбирает `UtilityAIComponent` по таблице и кривым, движение задают Lua-действия.

## Открытие

В консоли разработчика Visual Studio x64 выполните из корня репозитория:

```powershell
git switch QA
cmake --preset x64-debug -B out/build/x64-qa-debug -DCMAKE_PROJECT_TOP_LEVEL_INCLUDES=
cmake --build out/build/x64-qa-debug --target Game Editor
```

Для прямого запуска откройте `ReactorLab/Launch.cmd`. В редакторе откройте `ReactorLab/ReactorLab.ggproject` через Open Project. Стартовая сцена — `res://Scenes/Main.level.json`.

Можно передать другую сборку явно:

```cmd
Launch.cmd "C:\path\to\Game.exe"
```

## Структура проекта

| Путь | Назначение |
|---|---|
| `ReactorLab.ggproject` | Манифест версии 1, корень ресурсов и стартовая сцена |
| `res/Scenes/Main.level.json` | Игровая сцена |
| `res/Scenes/Autoplay.level.json` | Та же игра с автоматическим маршрутом игрока |
| `res/Scenes/Tests.level.json` | Общий регрессионный сценарий четырёх систем |
| `res/Scenes/Check*.level.json` | Независимые проверки таймеров, событий, триггеров и Utility AI |
| `res/Scenes/Repro*.level.json` | Регрессии чтения Lua-свойств |
| `res/Scripts` | Логика игры, регистрация экземпляров, индикаторы, тесты |
| `res/AI` | Таблицы UtilityAI, кривые и Lua-действия |
| `res/Materials`, `res/Textures` | Материалы и текстуры; надписи запечены в PNG |
| `verification` | Исторические результаты на бинарнике из исходного архива |

Каждый объект и компонент сериализован штатным форматом движка. Timer и UtilityAI находятся в обычных компонентах объекта; визуальные, физические и Lua-компоненты — в TransformTree. Размер визуального элемента задан дочерней веткой, чтобы не менять размер физического тела. Ссылки на ресурсы используют `res://`, согласно текущей реализации и LUA_API.md.

`World.lua` — небольшой реестр живых Lua-экземпляров сцены, поскольку публичного поиска объектов по именам нет. Он не владеет C++-объектами. Игровое состояние хранится в экземплярах компонентов. Проект не добавляет систем в движок.

## Проверки

Из PowerShell в папке ReactorLab:

```powershell
.\Test.ps1 -Scene CheckTimer
.\Test.ps1 -Scene CheckDelegates
.\Test.ps1 -Scene CheckTrigger
.\Test.ps1 -Scene CheckAI
```

Скрипт проверяет результат сцены и код выхода `0` после штатного закрытия игры. Журналы пишутся в `out/verification/ReactorLab` в отдельную папку для каждого запуска.

```powershell
.\Test.ps1                 # общий сценарий, включая физические входы/выходы
.\Test.ps1 -Autoplay       # автоматический сбор трёх блоков и выход
```

Регрессии можно запустить с `-Scene ReproTimerEvent`, `-Scene ReproTriggerEvent` и `-Scene ReproInstance`. По умолчанию запускатели ищут `x64-qa-debug`, затем `x64-release` и `x64-debug`. Чтобы выбрать сборку явно, передайте `-GameExe "C:\path\to\Game.exe"` в `Test.ps1`.

Персонажи кинематические, границы площадки ограничены в Lua. Интерфейс сцены собран из материалов с готовыми текстурами.
