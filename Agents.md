##О проекте
- Трениоровачный и учебный игровой движок на с рендером на dx11
- В результате должны получить редактор игрового движка, на котором возможно будет собрать игру.

##Особенности движка
- TransformTree. Каждый объект владеет TransformTree, куда можно добавлять ветки и называть и, создавая "слоты", а компоненты используют ветки

##Архитектура
- Общая архитектура через вложенность Game -> Level -> Object -> Component. Это также иерархия владения. 
- Object также владеет TransformTree. TransformTree владеет своими TransformableComponent 
- Будут множество логических структур (называться будут ...Item). Они нужны, чтобы системы получали данные об игре.
- Данными Item должны владеть компоненты. Остальные системы должны их использовать.
- Управление ресурсами схожее с Godot (класс Resource, кеширование ресурсов)
- Интерфейс на IMGUI с небольшими расширениями
- Скриптинг на Lua
- Физика на Jolt
- Движок - библиотека, редактор - отдельное приложение, использующее движок, игра - отдельный проект, запускаемый движком
- Ожидается наличие 2-х вариаций игр, запускаемая редактором и экспортный вариант (собранная игра)
- Особенность - дерево трансформации является отдельной системой. Объект хранит это дерево, а компоненты используют ветки
- Все ресурсы игры это файла, из-за чего проект игры просто считывает все файлы.

## Пути ресурсов
- Пути пока являются обычными std::string в UTF-8 с разделителем `/`; отдельная кроссплатформенная абстракция не нужна.
- Относительные пути считаются от рабочей директории процесса, например `res/Materials/Stone.material.json`.
- `res` — корень ресурсов, а не корень всего проекта. ContentBrowser получает этот путь из Editor/main.cpp.
- Текущий тестовый проект редактора находится в `%AppData%/GGEngine/TestProject`; папка `res` внутри него автоматически создаётся при запуске. ContentBrowser получает абсолютный путь к ней, независимо от рабочей директории.
- Используются непосредственные файловые пути, без `res://`, постоянных ID и файлов `.import`.
- За сохранность ссылок при переименовании и перемещении отвечает автор игры.
- Неудачная загрузка возвращает nullptr и ошибку ResourceManager; уже закешированные ресурсы остаются доступны до уничтожения менеджера.

##Правила работы
- Редактируй CMake только с разрешения и явным указанием того, что редактировать
- Самостоятельно не используй умные указатели. Только если указано, как будет соблюдаться владение, либо предложи свою идею и разрешение
- НЕ используй исключения
- НЕ создавай новые файлы. При необходимости - спроси
- Тестируй код только на то, собирается он или нет. 
- Если код не собирается, но НЕ из-за написанного тобою кода, не исправляй, а сообщи об этом.
- Для крупных изменений в начале спланируй желаемое, утверди план, и после положительного утверждения приступай к реализации.
- Если для полноценной работы нужны какие-то библиотеки - спроси разрешение на их добавление в CMake.
- Если нужны какие-то системы, которых на данный момент нет - не создавай их сам, а предложи идею и спроси разрешение.
- На каждые 2-3 строки кода делай короткие комментарий, поясняющий, что делает код. Если код очевиден - не пиши комментарий.
